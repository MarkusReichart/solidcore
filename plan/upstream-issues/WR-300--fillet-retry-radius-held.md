#### WR-300. `SmFilletVertex::CalcRailIntEdgeuse` holds a variable round's radius in its retry rail search at a non-constant-radius corner
- **Severity:** Wrong result (a variable round fails with `SM_ERR`, or through SM_API removes too much material)
- **Area:** Blend
- **Location:** `source/SMLib/src/SmFilletGeom.cpp:2006` (`SmFilletVertex::CalcRailIntEdgeuse`, the retry with a doubled extension, [B465]): `SmTemporaryRadiusChange sTempRad( pFilletGeom1->GetFilletSolver(), ... )` is unconditional; the first search (`:1977`-`1980`) passes the solver only when `GetFilletCorner()->IsCalcAsConstRad()`.
- **What happens:** at a corner not calculated as constant radius, the retry finds the rail end at the law's end radius rather than the radius the law gives there. The trace cannot pass through that point: `DoPointIntersection` rejects it as off both offset surfaces.
- **Trigger:** SolidCraft ladder 07-fillets/012: the retry found the arc's end (60, 35, 20) at r = 5 where the law gives 5.3636; the trace's first point (60, 34.636, 15) against (60, 35, 14.636) is rejected and the blend returns 1001. Through SM_API the same input silently removed 3.8 mm³ too much.
- **How found:** SolidCraft regression rig on the SMLib fork (tangency-labs/solidcore#1023).
- **Confirmed:** no (read at c9c5979 `source/SMLib/src/SmFilletGeom.cpp:2006` against `:1977`-`1980`; reproduced on the SolidCraft fork build: capi regression test in `ops_kernel.cpp`, laws 1→5 and 2→5 then match a closed-form model to about 1.5e-7 of the body).
- **Fix:** the retry holds the radius only where the first search does (passes `NULL` to `SmTemporaryRadiusChange` unless the corner is calculated as constant radius). The rail then misses the arc, and the existing end handling cuts the round off against the body.
- **Rust port:** opt-in `Kernel::fillet_retry_radius_as_first` (default `false`, upstream behaviour), read by `retry_holds_radius` in `crates/solidcore/src/blend/fillet_geom/p2.rs`; documented in that file's Deviations. Test `issue_1023_retry_holds_radius_only_as_first`. No difftest case compares the opt-in path (`SmTemporaryRadiusChange::SetUp` for a solver is still `UNPORTED(blend.fillet_executive_p2)`, so with the default those cases stay deferred). Fixes tangency-labs/solidcore#1023.
