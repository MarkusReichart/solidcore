# blend.fillet_corner_p1: fork feature, an Nx1 corner's unreachable end rib is handed to the global merge (2026-10-26)

Not an upstream-issues record: the refusal runs through pinned code (`SmFilletCorner.cpp:1609` `CalcCornerEdgeGeom` → `SmFilletGeom.cpp:6168` `SmFilletEdge::CalcFilletIntSideFace`), but it was seen only on the fork build and on upstream 3fd5b95 (Release 1.0.1, not an ancestor of our pin), never against c9c5979. The fix is the fork's `SmFilletNx1Corner::CalcCornerEdgeGeom` override. It was drafted as WR-303 and never merged under that id. Ported here as an opt-in fork feature.

- **Severity:** Blend failure (`SM_ERR` 1001, "Corner Edge Computation Failure", `SM_FCR_N_x_1`)
- **Area:** Blend
- **Location:** `source/SMLib/src/SmFilletCorner.cpp` (`SmFilletCorner::CalcCornerEdgeGeom`, run for `SmFilletNx1Corner`; `SmFilletEdge::CalcFilletIntSideFace` refuses the end rib); `SmFilletCorner.h:142` (`CalcCornerEdgeGeom` is not virtual).
- **What happens:** at a vertex of uniform convexity with only three edges, the one corner edge is the end rib, from one rail's end on its side edge to the other's. When the side edge ends within the fillet's width (a top round's end arc shortened by another round), the rail on that face never reaches it: its fillet vertex keeps `SM_FV_NO_INT_RAIL_EU` at (0, 0, 0) and the rib fails. SMLib hands such a round end to the global merge only when the vertex has more than three edges.
- **Trigger:** a 60 x 40 x 20 box at the origin: round the top back edge r5, then the top right edge alone r3, then the vertical edge x = 60, y = 40 with r7 (r4 and r2 fail too). The third round's end vertex (60, 40, 15) has three edges; the r5 round's end arc on the x = 60 face is 0.46 long.
- **How found:** SolidCraft regression rig on the SMLib fork (tangency-labs/solidcore#841); confirmed in gdb on stock 3fd5b95.
- **Confirmed:** on the fork's C++ build: r7, r4 and r2 each give one valid 9-face body, volumes within about 1e-7 of an independent integral (r7: 47418.926890 vs 47418.926881).
- **Fix:** an `SmFilletNx1Corner::CalcCornerEdgeGeom` override: when the corner's only edge is the end rib (`SM_FE_FILLET_X_SIDE_FACE`), one rail missed its side edge (`SM_FV_NO_INT_RAIL_EU`, the other end processed) and that side edge does not lie on the fillet's other side surface (`SimpleCoincidenceChecker`), set the executive's global merge, delete the rib and empty `m_vEdges`, so the merge cuts the round off where it meets the body. A side edge that only continues the filleted edge (a hole's rim split at a vertex) keeps the rib, refused as before.
- **Rust port:** opt-in `Kernel::fixes.fillet_nx1_end_rib_global_merge` (default `false`, upstream behaviour): `FilletCorner::nx1_unreachable_end_rib` in `crates/solidcore/src/blend/fillet_corner/p1.rs`, called from `FilletCorner::calc_corner_edge_geom` and the fillet session's corner-edge stage. The rib's deletion is `FilletBrep::delete_edge` (`topology.brep_p4`'s wire branch on the pseudo B-rep; it was `UNPORTED(topology.brep_p4)`), test `issue_841_pseudo_delete_edge_removes_a_wire_edge`. Default off, so no difftest case changes. Fixes tangency-labs/solidcore#841 (its rail check is `plan/findings/blend.fillet_solver_p5--fork-rails-fit-their-faces.md`).
